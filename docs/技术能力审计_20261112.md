## 一、先说三个必须知道的更正

### 1. 上游开源的核心包不在仓库里，`main.py` 跑不通

```
$ python main.py --help
ModuleNotFoundError: No module named 'badminton_analysis'
```

- 上游 [yo-WASSUP/Good-Badminton](https://github.com/yo-WASSUP/Good-Badminton)（Apache-2.0）的真正主体是
  `badminton_analysis/`（检测/球场映射/统计/可视化）+ `webui/`（Gradio 界面）。
- **这两块在你的仓库和 D 盘副本里都不存在**（目录为空或缺失），只剩一个入口文件 `main.py`。
- 影响：**「上传视频 → 姿态+球场+统计」这条开源能力，你现在实际上是拿不到的**；
  我在 11-07 说过"Gradio webui 现成"——那句话是错的，当时依据的是 D 盘的目录名而非内容。

### 2. 球检测权重不是你训练的

```
weights/yolo11s-ball.pt 元数据：
  model   = runs\detect\train17\weights\last.pt
  data    = datasets/badminton.yaml
  epochs  = 200, imgsz = 640
  date    = 2024-10-10T00:52
  version = ultralytics 8.3.7
  类别名  = {0: 'badminton'}
```

- 训练时间是 **2024-10**，那时你还没入学；这是别人训练的第三方权重，你只是拿来用。
- 顺带一个问题：它按 **imgsz=640** 训练，而我们推理用的是 **1280**，尺度不匹配会掉精度。
- **对外表述必须写成"基于公开的羽毛球检测权重"**，不能算你的成果；许可来源也不明，商用有风险。

### 3. 「开源能做到」的那部分，你实际上是自己重写的

上游能力缺失后，所有能跑的东西都是围绕你自己的扩展模块重建的。

## 三、真的可以使用吗（分场景，不美化）

| 场景 | 结论 | 依据 |
|---|---|---|
| **答辩/路演/GitHub 展示** | ✅ 可以 | `simulate` 一条命令出 3D 误差 18.9mm + 4/4 判罚 + 3D 视图；GUI 可拖视频演示；自检 6/6 |
| **实验室单机位、自拍素材、给同学看** | ⚠️ 有条件可以 | 需：①固定机位且四角全在画面 ②手动点四角标定 ③球轨迹连续跟到落地。三条同时满足才出判罚 |
| **任意网上下载的视频直接出判罚** | ❌ 不行 | 3 段真实素材实测：1 段标定正确但轨迹选错、1 段假标定被自检拦下、1 段近端底线被裁掉 |
| **交付级/商用判罚** | ❌ 不行 | 单目落点是地平面单应估算（非三维重建），误差无保证；YOLO 为 AGPL；检测连续性不足 |

### 落点判罚为什么条件这么苛刻

单目视频只有 2D。落点靠"球落地那一帧 + 地面单应矩阵"反推，因此：

1. **球必须被跟到落地**：球在空中丢失 → 映射出 -40m 这种荒谬值 → 现在会明确报 `still_in_flight`（宁可不判）；
2. **标定必须正确**：标定错 → 全部位置错 → 现在有几何自检 + 标定-轨迹自洽性校验（≥60% 轨迹点须落在球场附近）；
3. 实测瓶颈在**检测连续性**：30fps 下单帧检测会漏掉快球，轨迹断成短段，无落地帧。

## 四、数字证据（可复现）

`benchmark_results.json`（20 个合成场景）：

| 方法 | 位置 RMSE 中位 (mm) | 落点误差中位 @70% 观测 (mm) |
|---|---|---|
| A. RK4 + 动态噪声 | 8.5 | **29.3** |
| B. RK4 + 固定噪声 | 16.2 | 19.0 |
| C. 纯卡尔曼 | 59.5 | 120.2 |
| D. 纯抛物线 | **5.0** | 50.0 |
| E. 线性外推 | 23.8 | 243.8 |

可读出的结论（诚实版）：
- **物理引擎的优势在"落点预测"**（29.3mm vs 抛物线 50mm），不在"跟踪平滑"（抛物线 5.0mm 反而最好）；
- 卡尔曼/线性外推在这套评测里明显更差；
- 这些全是**合成数据**，不是实拍，不能当作产品精度对外宣称。

其他实测：双目模拟 13.4m 大基线 → 3D 误差均值 18.9mm / P95 42.4mm（合成）；
0.5m 小基线同条件 → 234.5mm。这组对比是你理论里最有说服力的一条。

## 五、三个必须先解决的事（按优先级）

1. **检测连续性**（决定"能不能真的判"）
   单帧 YOLO → 换时序模型（TrackNetV3，MIT 许可）或做多帧插值+轨迹补全。
   验收：同一段视频里球轨迹的"可见帧覆盖率"从现在的 10~20% 提到 70%+。

2. **标定可靠性**（决定"判得准不准"）
   自动标定在广角/多场地画面不可靠。务实做法：**强制手动四点**为标准流程（GUI 已支持），
   自动检测只作为"候选建议"，不通过几何自检就绝不采用。

3. **权重与许可**（决定"能不能对外"）
   - `yolo11s-ball.pt` 来源不明（2024-10 第三方训练），需换成语义清晰的来源或自己微调；
   - Ultralytics AGPL-3.0：公开演示没问题，**对外提供服务/商业化必须处理**（开源或购买商业授权）；
   - 上游 Apache-2.0 声明已保留在 LICENSE 与 README。

## 六、一句话总结

**现在这套东西是一个"能演示、能继续开发、但不能对外承诺精度"的原型。**
真正属于你的部分：RK4 物理引擎 + 多方法融合判罚 + 标定/误差传播理论 + 这轮补的工程链路；
真正卡住的部分：检测连续性（靠第三方权重和单帧检测）与单目标定可靠性。
把这两块补上，它才从"原型"变成"工具"。
