# 一、先修正目前项目中几个关键表述

这些内容必须写进新提示词，避免Claude把初步结果当成已证实事实。

## 2. “误差来源占比”暂时只是初步估计

你写的：

- 球参数35%；
- 观测噪声30%；
- 轨迹过短25%；

如果没有正式方差分解或Sobol敏感性分析，这些比例不能直接作为论文结论。

应改成：

## 3. “100 fps以下精度损失约12%”需要重新复现

除非已经有完整的：

- 130/100/80/60/50/30 fps对照；
- 相同轨迹配对降采样；
- 置信区间；
- 原始结果文件；

否则要标记为：

---

## 4. 7个实验中的统计方法需要修正

| 实验 | 原统计方案 | 建议修正 |
|---|---|---|
| 非对称阻力 | 配对t检验 | 配对Bootstrap + Wilcoxon；t检验作为辅助 |
| 相位感知融合 | McNemar | McNemar比较40mm通过率，同时配对Bootstrap比较P95 |
| 梯度提升融合 | 5-fold嵌套CV | 正确，但必须按轨迹分组，不能按帧 |
| Bootstrap判罚 | Brier + 校准 | 正确，再加覆盖率和风险—覆盖率 |
| 贝叶斯融合 | 后验覆盖 | 加CRPS/Brier/预测区间面积 |
| 序贯假设检验 | Kappa | Kappa不是序贯检验；应测试I/II类错误、停止时间和提前判罚率 |
| JointFit v2 | DeLong | DeLong主要比较ROC AUC，不适合落点连续误差；改用配对Bootstrap、Wilcoxon、McNemar |

多重比较建议用**Holm校正**，比统一Bonferroni更合适。

---

## 5. 36只球参数测量不能直接得到drag系数

质量可以直接称重，尺寸可以测量；但drag系数一般不能仅凭质量、截面积直接得到。

更合理流程是：

1. 测质量和几何尺寸；
2. 记录每只球的多条高质量轨迹；
3. 在已标定观测下反演等效阻力参数；
4. 给出参数置信区间；
5. 评估同球内和不同球之间的变异。

# 十、聊天框6提示词：JointFit v2真正共同拟合

你原来的JointFit公式不够清楚，因为六种方法不一定共享同一个参数\(\theta\)。建议让Claude按“共识落点”实现。

```text
本聊天任务：实现JointFit v2连续共同拟合，使多个模型在各自参数空间中拟合同一观测，并通过共同落点变量形成共识。

不要简单使用一个theta强行代替六个模型的不同参数。

推荐数学形式：

对每个模型m定义自己的参数theta_m；
定义共同落点p；
g_m(theta_m)为模型m由参数得到的落点。

优化：

min over p, theta_1...theta_M

sum_m w_m [
    L_obs_m(theta_m)
    + lambda_m * ||g_m(theta_m)-p||^2_{Sigma_m^-1}
]
+ parameter_regularization
+ weight_regularization

其中：
L_obs_m是该模型轨迹对已观测历史段的鲁棒加权残差；
p是所有模型共同优化的连续落点；
Sigma_m是模型落点不确定性；
权重不能无约束塌缩到单一模型。

实现以下版本：

J0：旧JointFit Adapter；
J1：固定权重共识JointFit；
J2：基于历史交叉评分权重的JointFit；
J3：带鲁棒共识损失的JointFit；
J4：可选的交替优化JointFit。

要求：

1. 每个模型保留自己的参数空间。
2. 共同优化变量必须明确。
3. 观测损失使用Huber或Student-t。
4. 落点共识损失必须支持协方差加权。
5. 参数必须有物理边界和先验/正则化。
6. 输出：
   convergence；
   number_of_iterations；
   objective_value；
   observation_loss；
   consensus_loss；
   parameter_bounds_hit；
   model_weights；
   runtime；
   failure_reason。
7. 防止权重全部集中到单一模型。
8. 支持多初值。
9. 支持超时和失败后回退到CrossScoring。
10. 不允许使用未来观测。
11. 检查参数可辨识性：
    灵敏度矩阵；
    参数相关性；
    条件数；
    多初值稳定性。
12. 比较时使用：
    配对Bootstrap；
    Wilcoxon；
    40mm通过率McNemar。
13. 不使用DeLong作为落点连续误差主检验。
14. 分别测试20%、40%、60%、80%观测比例。
15. JointFit较慢，因此配置中支持：
    max_iterations；
    timeout_seconds；
    number_of_initializations；
    parallel_jobs。
16. 不运行正式实验。

实现：

src/good_badminton/jointfit/objective.py
src/good_badminton/jointfit/consensus.py
src/good_badminton/jointfit/optimizer.py
src/good_badminton/jointfit/diagnostics.py
tests/test_jointfit_consensus.py
tests/test_jointfit_no_future_leakage.py
```

# 十四、明天真实采集需要注意

你计划的30～50条轨迹只能作为：

- 相机可用性验证；
- 同步验证；
- 初步定位噪声估计；
- 仿真—现实偏差估计；
- Pipeline端到端打通。

**不能用30～50条证明99%商业精度。**

尤其注意：

## Ground truth

普通胶带标记的误差可能已经接近厘米级。至少要记录：

- 胶带边界位置；
- 球第一次接触点；
- 测量工具精度；
- 两名标注者；
- 标注分歧；
- 是否发生反弹、滑动；
- 球头和羽毛裙哪个先接触。

## 真实数据优先拿来估计

1. 左右同步误差；
2. 像素定位误差；
3. 三角化误差；
4. 曝光模糊长度；
5. 漏检模式；
6. 连续遮挡长度；
7. 合成模型和真实轨迹之间的残差。

这样理论代码可以直接把真实误差分布装进配置文件，进行第二轮域校准。
