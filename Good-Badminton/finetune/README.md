# 微调流程：用西电羽球队数据做领域自适应

> 目标不是从零训练，而是**把公开数据上预训练的球检测模型，适配到西电球馆的真实条件**
> （场地色调、灯光、机位、球速、球员服装），让漏检和误检在自家素材上明显下降。
>
> 这段流程对应领飞科创选题里"数据整理标注 + 代码复现"两项任务，也是报告里最硬的一章：
> **微调前后的量化对比表**。

---

## 一、为什么必须微调（而不是直接用现成权重）

预训练权重来自转播/公开素材：机位高、光线均匀、球场标准化。西电球馆的差异在于

| 维度 | 公开转播素材 | 西电竞赛/训练视频 |
|---|---|---|
| 机位 | 高位固定、单场地 | 手持或低机位、多场地同框 |
| 光照 | 均匀演播室光 | 顶灯不均、局部逆光、球馆偏黄/偏绿 |
| 场地 | 标准绿/蓝 | 塑胶深浅不一、积水反光 |
| 球 | 白球 vs 深背景 | 常出现白线、白鞋、白毛巾等干扰 |
| 运动模糊 | 高速快门 | 手机/普通相机卷帘、拖尾长 |

结果就是：**在其他素材上跑得好，在自家球馆里误检和漏检都会明显上升**——这正是微调要解决的问题。

## 二、数据采集规范（单机位版）

老师目前只要**一个机位**，所以采集规范按单机位收紧，重点是"条件要变、机位不变"。

### 2.1 硬件与设置

| 项目 | 要求 |
|---|---|
| 设备 | 手机 / 相机 / 运动相机均可，**分辨率 ≥1080p** |
| 帧率 | ≥30fps；**60fps 优先**（扣杀拖尾更短、球更清楚、标注更容易） |
| 固定方式 | **三脚架固定**，全程不动；手持只在实在没条件时用 |
| 防抖 | **关闭数码/电子防抖**（会造成画面非线性形变，破坏球场标定） |
| 焦距 | 固定，关闭自动变焦与自动追焦 |
| 曝光 | 尽量锁定曝光；避免顶灯直射镜头产生眩光 |

### 2.2 机位怎么摆（这是唯一一次要动脑子的事）

推荐：**底线后方居中，高度 2.5~3.5 m，俯角 15°~25°**

三条硬性要求：
1. **整套双打场地的四个角必须都在画面里** —— 后面的落点判罚靠四个角做透视标定，缺一个角就废；
2. **球网完整可见**，网柱不要被裁掉；
3. 球在画面里不能太小：如果球只有 2~3 像素，模型学不动，宁可机位近一点、只拍半场。

摆好之后不再移动。**同一机位只需标定一次**，程序会把四角存进 `calib_single_cam.json`，
后面所有同机位视频自动复用（换场地/换机位时在窗口点「清除标定」重新来一次）。

### 2.3 拍什么（机位固定，但"条件"必须变）

单机位的最大风险是**模型只认这一种视角**，到了别的光线、别的球速就废。所以采集要刻意覆盖：

| 维度 | 要求 |
|---|---|
| 时段 | 至少 **2 个不同时段**：白天自然光 + 夜间开灯（球馆灯光是最大变量） |
| 球路 | 高远、吊球、扣杀、平抽、网前搓放**各都要拍到** |
| 球员 | 男女各若干、深色/浅色服装都要有（防止模型把白球衣学成球） |
| 干扰物 | 画面里要有白线密集区、白毛巾、白色球鞋、场边白色标识 |
| 球况 | 新球 + 打旧的球都拍一点（旧球整洁度不同，视觉差异明显） |
| 时长 | 每场 15~30 分钟，**总计 30 分钟以上素材**起步 |

### 2.4 命名与归档

机位固定，所以按「日期_时段_场地」归档即可：

```
raw/
  2026-11-10_day_courtA/   clip01.mp4  clip02.mp4
  2026-11-12_night_courtA/ clip01.mp4
```

> ⚠️ **train/val 必须按"日期/场次"整段划分**，不能按帧随机分。
> 同一场次相邻帧几乎一模一样，按帧分会让指标虚高（数据泄漏）。
> 单机位设置下这仍是硬要求——划分依据从"机位"换成"场次"。

## 三、标注规范（只在预标注基础上修正，不要从零标）

- **类别只有一个**：`ball`（类别 0）。不需要区分球头/球裙
- **框的规范**：正好框住羽毛球可见像素（含运动拖尾则框到拖尾端点），不要人为放大
- **遮挡**：球被球员/球网遮住但能判断位置时标；完全不可见则不标（别猜）
- **负样本很重要**：画面里有白鞋、白线、白毛巾但**没有球**的帧，保留为**空标注**——
  这是压低误检最有效的手段，`prepare_dataset.py --neg-ratio` 默认保留 30%
- **一致性**：同一段视频内框的宽严标准要统一，否则模型学不到稳定尺度

## 四、工作量估算（跟老师汇报用）

| 环节 | 数量 | 预标注能省多少 |
|---|---|---|
| 抽帧 | 30 分钟素材 → 约 600~1200 帧（脚本自动、去重去模糊） | 全自动 |
| 预标注 | 同批帧由 `yolo11s-ball.pt` 自动打框 | 省去 100% 的"从零打框" |
| 人工修正 | 每帧平均 5~15 秒（多数只需确认，少数补框/删框） | **比纯手工省 70~80%** |
| 600 帧修正总工时 | 约 1.5~2.5 小时 / 人 | — |

> 汇报口径：**"纯手工标注 600 帧约需 8~10 小时；采用预标注+修正后约 2 小时，效率提升约 4 倍"**。
> 这个数字要按实际测一次再写进材料，别直接用估算值。

## 五、执行流程（三步命令）

```bash
cd Good-Badminton

# 1) 从采集素材构建数据集（自动抽帧 + 预标注 + 划分 train/val）
python finetune/prepare_dataset.py \
    --videos "D:/xtu_raw" \
    --out finetune/dataset \
    --frames-per-video 150 \
    --conf 0.20

# 2) 用 LabelImg / Label Studio 打开 finetune/dataset/images，
#    对照 labels/ 里的预标注做修正（删误检、补漏检、保留负样本）

# 3) 微调（有 GPU 时去掉 --device cpu；无 GPU 先小规模验证流程）
python finetune/train.py \
    --data finetune/dataset/data.yaml \
    --epochs 100 --imgsz 1280 --batch 8 --device auto \
    --freeze 10 --lr0 0.001

# 4) 评估 + 与原始权重对比（这张对比表就是报告核心数据）
python finetune/evaluate.py \
    --compare weights/yolo11s-ball.pt weights/yolo11s-ball-xtu.pt \
    --data finetune/dataset/data.yaml
```

训练完成后权重会复制到 `weights/yolo11s-ball-xtu.pt`，`video_pipeline.py` 检测时自动优先使用
（见主 README「自定义权重」一节）。

## 六、验收指标（别只看 loss）

在**留出的西电素材**（不参与训练）上评估：

| 指标 | 及格 | 目标 |
|---|---|---|
| Recall（召回） | ≥ 0.75 | ≥ 0.85 |
| Precision | ≥ 0.70 | ≥ 0.85 |
| 误检密度（非球白点被当球） | ≤ 5 点/帧 | ≤ 1 点/帧 |
| 单帧推理耗时（CPU/GPU） | — | 记录即可 |

**分场景分开报**：按机位（底线/侧面）、光照（白天/夜间）分组出表，比单一平均值更有说服力。

## 七、迭代循环（做完一轮之后）

1. 用新权重跑 `video_pipeline.py` 分析留出视频；
2. 把**漏检/误检的帧**（脚本会输出轨迹与预览图）挑出来 → 正是 badcase；
3. 这些帧补进数据集（`--frames-per-video` 单独跑一遍这些视频）→ 重新微调；
4. 每轮记一次评估表，形成"迭代 1 / 2 / 3"的曲线——报告里非常好看。

## 八、注意事项

- **训练和验证必须按视频划分**，不能按帧随机划分（同一段视频的相邻帧几乎一样，会造成数据泄漏、指标虚高）。
  当前脚本按帧随机分（小规模验证用），正式训练请用 `--val-ratio` 之外的方式：按视频整段分配到 train/val。
- 冻结 backbone（`--freeze 10`）在小数据集（<1000 张）上更稳，过拟合风险低。
- 不打水平翻转（`fliplr=0`）：球轨迹有方向语义，翻转会引入错误先验。
- 权重文件体积较大，**不入 git**（`.gitignore` 已排除 `weights/`），交接时单独拷贝或用网盘。
